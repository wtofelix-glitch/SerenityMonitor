# 文档D：信号台设计（骨架）

> Serenity 2.0 第2阶段 | 2026-07-22 | ⚠️ 骨架版，不含具体买卖阈值
> 目标：定义信号从情报到建议的转换框架，具体参数后续结合历史数据验证

---

## 1. 信号生成五步流程

```
EventRecord（经过验证的情报）
  │
  ├─ Step 1: 市场环境检查
  │   市场体制（震荡/趋势/极端）
  │   当日流动性（量能是否正常）
  │   大盘风险（涨跌/涨跌比）
  │   → 不通过则降级为观察
  │
  ├─ Step 2: 个股趋势检查
  │   多周期趋势方向
  │   关键支撑/阻力位置
  │   相对于大盘的强弱
  │
  ├─ Step 3: 量价确认
  │   量价是否配合
  │   资金流向是否支持
  │   是否有背离信号
  │
  ├─ Step 4: 事件确认
  │   情报与趋势是否一致
  │   事件影响与账户是否相关
  │   是否存在矛盾情报
  │
  ├─ Step 5: 账户适配
  │   当前持仓与现金
  │   仓位约束
  │   风险敞口
  │
  └─ → 候选行动信号
```

---

## 2. 三级信号定义（精炼版）

### 🚨 P0 行动信号

**定义**：满足"环境+趋势+量价+事件+账户"五步全部通过的情报。
**产出**：明确买卖建议 + 价格区间 + 仓位 + 止损 + 失效条件。
**频率**：不限（但门槛极高，应很少触发）。
**操作**：立即推送，由你确认后执行。

### ⚠️ P1 关注信号

**定义**：满足环境+趋势+量价，但事件确认或账户适配未完全通过。
**产出**：当前状态描述 + 关键观察条件 + 建议准备（非执行）。
**频率**：盘中≤3条。
**操作**：按规则推送，进入关注清单。

### 👀 P2 情报信号

**定义**：仅满足环境检查，其他步骤未触发或信息不足。
**产出**：情报摘要 + 相关性说明。
**频率**：不单独推送，日终汇总。
**操作**：知道即可。

```
┌─────────────────────────────────────────────────┐

│  触发依据（含引用数据源）：                        │

│  [2] XXXX                                        │
│                                                  │
│  数据更新时间：[时间]                              │
└─────────────────────────────────────────────────┘
```

## 4. 信号置信度规则（骨架）

| 置信度 | 条件 | 对应动作 |
|:-----:|:-----|:--------|
| **高** | 五步全通过 + 验证状态=verified + 盈亏比>2:1 | 可以执行 |
| **中** | 五步通过3-4步 + 验证无冲突 | 可以执行但需额外确认 |
| **低** | 五步通过≤2步 | 仅进入观察清单 |

> 具体置信度计算公式（如加权评分/阈值判定）需结合历史回测数据确定。
> 第一阶段可使用固定规则：每通过1步=20分，≥80=高，50-79=中，<50=低

---

## 5. 信号复盘与参数调整

| 复盘维度 | 记录字段 | 调整机制 |
|:--------|:--------|:--------|
| 胜率 | 信号方向 vs 实际走势 | 月累计 |
| 盈亏比 | 平均盈利 vs 平均亏损 | 月累计 |
| 延迟 | 信号时间 vs 执行时间 vs 结果时间 | 事后分析 |
| 误报率 | P0/P1中未产生实际交易的信号占比 | 周统计 |
| 用户采用率 | 用户确认执行的信号占比 | 月统计 |

## 6. 与文档C的接口

```
C层（情报网）          D层（信号台）
  │                       │
  EventRecord ──────────→ 五步验证
  (verified情报)           │
                           ├→ P0 行动信号
                           ├→ P1 关注信号
                           └→ P2 情报信号
                              │
                              ↓
                         B层（账户基线）
                         检查仓位/风险约束
                              │
                              ↓
                         你（最终决策）
                         确认/拒绝/修改
                              │
                              ↓
                         回填成交
                         更新账户基线
```
